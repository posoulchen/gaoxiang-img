## ② 核心知识精讲

### 2.1 运维管理：把服务稳稳交出去

运维管理的目标是保障信息系统安全、稳定、高效运行，以可接受的成本达成约定的服务水平。它不追求"零故障"——那在经济上不成立，它追求的是"故障影响可控、恢复速度可承诺"。

ITIL 把 IT 服务管理组织成一条服务生命周期：服务战略、服务设计、服务转换、服务运营、持续服务改进。落到日常，运维的核心流程包括事件管理、问题管理、变更管理、配置管理、发布管理、服务级别管理、容量管理、可用性管理和连续性管理。这些流程不是并列的清单，而是互相咬合的齿轮：变更会引发事件，事件的根因沉淀为问题，问题通过变更解决，变更又必须更新配置。

三块最常被考的具体抓手：

- 监控：基础设施监控（主机、网络、存储）、应用性能监控（响应时间、交易成功率、慢查询）、日志与链路追踪、告警分级与值班响应、定期巡检。监控的价值不在"能报"，而在"早报、准报、能定位"。
- 容量管理：分三层看——业务容量（业务量预测与峰值）、服务容量（服务能承载多少并发与吞吐）、组件容量（CPU、内存、存储、带宽）。容量管理的产出是容量计划与扩容方案，不是等告警了再买机器。
- 可用性管理：可用性 = MTBF ÷（MTBF + MTTR）。MTBF 是平均故障间隔时间（反映稳定性），MTTR 是平均修复时间（反映恢复能力）。算例：MTBF = 495 小时、MTTR = 5 小时，可用性 = 495 ÷ 500 = 99%。

要点提示：提升可用性有两条路——拉长 MTBF（提高可靠性、冗余设计）和压缩 MTTR（监控告警、预案、自动化切换）。很多单位只砸钱买冗余，却不管演练，MTTR 压不下来，可用性照样不达标。

### 2.2 信息安全策略体系：四级文件自上而下

| 层级 | 内容 | 签发/使用 |
|---|---|---|
| 一级 | 信息安全方针（总纲） | 最高管理者签发，表明承诺与方向 |
| 二级 | 管理制度与策略 | 分类分级、访问控制、账号、备份、应急 |
| 三级 | 操作规程与流程 | 具体怎么做，如账号申请与审批步骤 |
| 四级 | 记录与表单 | 执行留痕，如审批单、巡检表 |

上层定原则，下层可执行，下层不得与上层冲突。安全管理体系则由五块组成：组织（安全委员会、安全负责人、岗位职责）、制度、技术、人员（培训、保密协议、离岗管理）、监督与考核。信息安全三性要背牢：保密性、完整性、可用性。

### 2.3 等级保护 2.0 与风险评估

等级保护 2.0 的总体架构是"一个中心、三重防护"：**安全管理中心**，加上**安全通信网络、安全区域边界、安全计算环境**三重防护。注意"一个中心"必须写出来，这是命题人最爱设的缺口——很多考生只写三重防护，直接丢分。

等级保护的工作流程是：定级、备案、建设整改、等级测评、监督检查。等级分五级，级别越高要求越严；三级及以上系统要按监管要求定期开展等级测评，二级系统按监管要求接受抽查。

风险评估的链条是：资产 → 威胁 → 脆弱性 → 可能性与影响 → 风险值 → 风险处置。处置有四种：规避（不做这件事）、降低（加控制措施）、转移（保险、外包）、接受（在容忍度内）。处置后剩下的叫残余风险，必须被明确接受或继续处置，不能装作不存在。

### 2.4 BCP 与 DRP：RTO、RPO 千万别搞反

BCP（业务连续性计划）面向整个组织，目标是让关键业务在中断后能持续运行或在可接受时间内恢复。它的起点是 BIA（业务影响分析）——先搞清楚哪些业务最关键、能停多久、会损失多少，再定恢复优先级和指标。

DRP（灾难恢复计划）是 BCP 中聚焦信息系统与数据恢复的那一部分，是 BCP 的子集，不是并列关系。灾备能力分三级：数据级（只保数据，恢复最慢）、应用级（备用系统可接管运行）、业务级（含人员、场地、流程的整体接管，成本最高）。

| 指标 | 含义 | 白话版 |
|---|---|---|
| RTO | 恢复时间目标 | 业务最多能停多久 |
| RPO | 恢复点目标 | 最多能丢多少数据 |
| MTD | 最大可容忍中断时间 | 底线，RTO 不得超过它 |

RTO 是时间维度，RPO 是数据维度，这是唯一不会错的判据。RTO 要求越短、RPO 要求越小，投入成本越高，所以必须由 BIA 定出来的业务需求来倒推，而不是由 IT 部门拍脑袋。

> **记忆抓手**：RTO 管"停多久"，RPO 管"丢多少"；BCP 管业务、DRP 管 IT，DRP 是 BCP 的子集；等保记"一个中心、三重防护"；可用性 = MTBF ÷（MTBF + MTTR）。

## ③ 高频易错点

1. **易错点**：把 RTO 和 RPO 记反。 → **正解**：RTO 是恢复所需时间（停多久），RPO 是恢复到的数据时点（丢多少）；看到"丢失""数据"就选 RPO。
2. **易错点**：认为 BCP 与 DRP 是并列或等同关系。 → **正解**：DRP 是 BCP 中专注 IT 与数据恢复的子集，BCP 还覆盖人员、场地、业务流程与对外沟通。
3. **易错点**：等保 2.0 只写"三重防护"，漏掉"安全管理中心"。 → **正解**：完整表述是"一个中心（安全管理中心）、三重防护（安全通信网络、安全区域边界、安全计算环境）"。
4. **易错点**：算可用性时把 MTTR 放到分子，或用 MTBF 除以 MTTR。 → **正解**：可用性 = MTBF ÷（MTBF + MTTR），分母是总运行时间。
5. **易错点**：认为风险处置完就没事了。 → **正解**：处置后要评估残余风险，明确接受或继续处置，并纳入监控。

## ⑤ 参考答案与解析

1.B　2.B　3.B　4.B　5.C　6.B　7.B　8.B

**1. B**　解析：RTO 是恢复时间目标，衡量业务能停多久。A 描述的是 RPO；C 是 MTBF；D 是备份策略参数，都不是 RTO（考点：RTO 的定义）。

**2. B**　解析："最多丢失多少数据"是数据维度，对应 RPO。RTO 管的是中断时长；MTTR 是平均修复时间；MTBF 是平均故障间隔，均与"丢数据"无关（考点：RTO 与 RPO 的区分）。

**3. B**　解析：DRP 是 BCP 的子集，聚焦 IT 系统与数据的恢复；BCP 覆盖业务、人员、场地、供应商与对外沟通。A 错在等同；C 把覆盖范围说反；D 错在 DRP 必须以 BIA 结论为依据（考点：BCP 与 DRP 的关系）。

**4. B**　解析：等级保护 2.0 的标准表述是"一个中心（安全管理中心）、三重防护（安全通信网络、安全区域边界、安全计算环境）"。其余选项的中心数与防护数均错（考点：等保 2.0 架构）。

**5. C**　解析：可用性 = MTBF ÷（MTBF + MTTR）= 495 ÷（495 + 5）= 99%。注意累计运行 500 小时已包含故障停机时间，分子必须是 495 而不是 500（考点：可用性计算）。

**6. B**　解析：从业务交易量预测出发推算资源需求，属业务容量管理。组件容量关注 CPU、内存、存储等单体资源；服务容量关注服务承载能力；可用性管理关注服务连续性指标（考点：容量管理三层）。

**7. B**　解析："未打补丁"是系统自身存在的弱点，属脆弱性；威胁是可能利用弱点的主体或事件（如黑客攻击）；影响是后果；资产是被保护对象（考点：风险评估要素）。

**8. B**　解析：信息安全方针是总纲，由最高管理者签发，表明承诺与方向；其下依次为管理制度、操作规程、记录表单。A 层级颠倒；C 记录表单属四级执行留痕；D 下层不得与上层冲突（考点：策略体系层级）。

**判断改错**　参考答案：该说法**不正确**。两者不是同一概念：**BCP（业务连续性计划）**面向整个组织，覆盖关键业务、人员、场地、供应商与对外沟通，目标是保障业务持续或在可接受时间内恢复；**DRP（灾难恢复计划）**是 BCP 的**组成部分（子集）**，聚焦**信息系统与数据**的恢复，其指标与优先级须以 **BIA（业务影响分析）** 结论为依据。改正为："DRP 是 BCP 中专注信息系统与数据恢复的子集，两者不等同，且均以 BIA 为依据。"采分关键词：**子集、业务连续性、信息系统与数据、BIA**。
