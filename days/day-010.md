## ② 核心知识精讲

### 2.1 三大任务：价值、风险、资源

IT 治理千头万绪，落到动作上就三件事，这三件事也是三条评价线。

**第一，价值交付（价值实现）。** 确保 IT 投入真正转化为业务收益：IT 战略与业务战略对齐，投资有明确的收益预期，项目交付后做收益评价，收益不达标要复盘。关键动作有三个——立项时做**商业论证**、执行中跟踪**效益实现**、收尾后做**投资后评价**。常见失手是"上了系统没人用、投入产出说不清"，本质是价值线断了。

**第二，风险管理。** 治理层要做的是**定风险偏好和容忍度**，而不是逐个去识别项目风险。也就是说，治理回答"我们能承受多大的风险"，管理回答"这个风险怎么应对"。配套动作包括：建立 IT 风险清单与分级标准、重大风险上报通道、重大变更与重大外包的风险评审、安全与合规底线。

**第三，资源管理（资源优化）。** 统筹 IT 的人力、资金、基础设施和信息资产，避免重复建设与资源闲置。典型动作是统一预算口径、统一架构与技术标准、建立共享资源池、清理低效系统。资源管理的目标是"同样的投入产出更多"，而不是"多要预算"。

三者之间是联动的：资源投错方向，价值就实现不了；风险失控，价值会被一次事故抹平；价值长期不达标，资源就再也申请不到。案例里分析治理问题，按这三条逐一对照，基本不会漏点。

> **记忆抓手**：价值问"值不值"，风险问"敢不敢"，资源问"够不够、浪不浪费"。三个字：值、险、源。

### 2.2 三大框架：一个管控制、一个管服务、一个管原则

框架这块最怕混，先把定位钉死：

| 框架 | 定位 | 主要用途 |
|---|---|---|
| COBIT | IT 治理与控制框架 | 建立控制目标、划分治理与管理职责、支撑审计评价 |
| ITIL | IT 服务管理最佳实践 | 规范服务生命周期与运维服务流程，提升服务质量 |
| ISO/IEC 38500 | 组织 IT 治理国际标准 | 给出治理原则与"评估—指导—监督"治理模型 |

**COBIT** 由 ISACA 发布，全称是"信息及相关技术的控制目标"。它的价值在于把治理落到**可审计的控制目标和管理实践**上，并明确区分治理与管理两层。COBIT 5 提出五条原则：满足干系人需求、覆盖企业端到端、应用单一集成框架、采用整体化方法、**区分治理与管理**。治理层对应"评估（Evaluate）—指导（Direct）—监督（Monitor）"三个动作，管理层的活动则围绕 APO（对齐、计划、组织）、BAI（构建、获取、实施）、DSS（交付、服务、支持）、MEA（监控、评价、评估）四块展开。考试不需要背全部目标，只要记住：**COBIT 是治理与控制框架，关键词是控制目标、审计、治理与管理分离**。

**ITIL** 是 IT 基础架构库，源自英国，是 **IT 服务管理（ITSM）** 的最佳实践集合。经典版本按服务生命周期组织：**服务战略、服务设计、服务转换、服务运营、持续服务改进**；ITIL 4 转向服务价值系统（SVS）与四维模型（组织与人员、信息与技术、合作伙伴与供应商、价值流与流程）。它管的是"服务怎么设计、怎么交付、怎么支持、怎么改进"，比如事件管理、问题管理、变更管理、服务台、SLA。

**ISO/IEC 38500** 是面向组织 IT 治理的国际标准，给出六项原则：**责任、战略、获取、绩效、合规、人的行为**；治理模型就是 **评估（Evaluate）—指导（Direct）—监督（Monitor）**。它的定位最高——不讲具体流程，只讲"治理层该怎么想、怎么管"。

三条判断线，考场上直接用：

- 题干出现"控制目标、审计、治理与管理职责划分"——**COBIT**；
- 题干出现"服务台、事件管理、SLA、服务生命周期"——**ITIL**；
- 题干出现"董事会、六项原则、评估指导监督"——**ISO/IEC 38500**。

注意一个反向陷阱：**ITIL 不是治理框架，而是管理框架**。命题人很喜欢把它写成"IT 治理的框架"，就等你上钩。

> **记忆抓手**：COBIT 管"控制与审计"，ITIL 管"服务与运维"，38500 管"原则与方向"。三句话：控、服、则。

### 2.3 治理、公司治理与风险管理：三层嵌套

这三者的关系是"由外到内、由大到小"：

**公司治理 → IT 治理 → IT 管理**。公司治理解决股东、董事会、管理层之间的权责安排；IT 治理是它在 IT 领域的延伸，把公司战略翻译成 IT 的投资方向与决策规则；IT 管理再把规则落成计划与交付。公司治理为 IT 治理提供制度环境，IT 治理向公司治理反馈 IT 的价值与风险。方向不能反，层级不能平。

**风险管理**在这里是"任务的交集"：它既是 IT 治理的三大任务之一，也是公司层面全面风险管理（ERM）的组成部分。治理层定风险偏好与容忍度、审批重大风险应对、决定管理储备的动用；管理层识别具体风险、制定应对措施、执行监控。这条线接到项目管理上就是：**应急储备用来应对已识别风险，包含在成本基准内，项目经理可动用；管理储备用来应对未知风险，不包含在成本基准内，动用需要高层批准**。这一点在案例和计算题里反复出现。

### 2.4 指标与落地：把三大任务翻译成数字

治理不能只喊口号，每一项任务都要有可度量的指标。

| 治理任务 | 关键问题 | 典型指标 |
|---|---|---|
| 价值交付 | IT 投入有没有换来收益 | IT 投资回报率、项目按期交付率、业务满意度 |
| 风险管理 | 底线守没守住 | 重大安全事件数、审计问题整改率、合规通过率 |
| 资源管理 | 资源用得省不省 | IT 成本占收入比、关键系统利用率、重复建设率 |

指标的使用有三个纪律：**口径统一**（同一个指标不能两套算法）、**定期评价**（按月或按季，不能一年看一次）、**结果挂钩**（评价结论要影响下一轮预算与立项）。否则指标就只是报表上的装饰。

还有一个常被考到的判断：治理指标看的是**组织层面**，项目管理指标看的是**单个项目层面**。同一个"按期交付率"，在项目里是进度管理的结果，在全组织口径下就是治理对价值实现的评价。

## ③ 高频易错点

1. **易错点**：把 ITIL 当成 IT 治理框架。 → **正解**：ITIL 是 IT 服务管理（ITSM）的最佳实践，属于管理框架；治理框架是 COBIT 和 ISO/IEC 38500。看到"服务台、事件管理"就选 ITIL。
2. **易错点**：认为 COBIT 是运维操作手册。 → **正解**：COBIT 提供的是控制目标与管理实践，用于治理、审计和职责划分，不规定具体怎么修故障。
3. **易错点**：把风险偏好的确定交给项目经理。 → **正解**：风险偏好和容忍度由治理层（董事会/最高管理层）确定，项目经理负责在既定偏好内识别和应对具体风险。
4. **易错点**：认为管理储备包含在成本基准内、项目经理可自行动用。 → **正解**：管理储备应对未知风险，**不包含**在成本基准内，动用须经高层批准；应急储备应对已识别风险，**包含**在成本基准内。
5. **易错点**：把三项治理任务割裂开看。 → **正解**：三者互相牵制——资源错配导致价值落空，风险失控吞噬价值，价值不达标又拿不到资源。案例答"治理问题"时要三条并列写。

今日无案例题，专注选择题。补一道判断改错题替代：

判断下列说法是否正确，错误的请改正。

- （1）ITIL 是 IT 治理框架，COBIT 是 IT 服务管理框架。
- （2）IT 治理的资源管理任务要求统筹 IT 资源、避免重复建设。
- （3）管理储备包含在成本基准之内，项目经理可以直接批准动用。

## ⑤ 参考答案与解析

**答案速查：1.B　2.C　3.B　4.B　5.B　6.B　7.B　8.B**

**1. B**　解析：IT 治理三大任务是价值交付、风险管理、资源管理。A 是管理过程的一般划分；C 是项目管理知识领域；D 是系统生命周期阶段，都与治理任务的表述不符。

**2. C**　解析：清理闲置系统、统一资源池与采购口径，解决的是资源重复配置与浪费问题，属于资源管理任务。A 关注投入是否换来收益；B 关注风险底线；D 是评价手段，不是任务本身。

**3. B**　解析：COBIT 是 ISACA 发布的 IT 治理与控制框架，核心是可审计的控制目标，并明确区分治理层与管理层职责。A 是 ITIL；C 是 CMMI；D 是等级保护标准。

**4. B**　解析：ITIL 是 IT 服务管理最佳实践，按服务战略、设计、转换、运营、持续改进组织，关注服务台、事件、问题、变更等流程。A、D 把治理框架的属性安到了 ITIL 上；C 是治理层职责，不属于 ITIL 范围。

**5. B**　解析：ISO/IEC 38500 用"评估—指导—监督"（EDM）描述治理层的三个动作，并给出责任、战略、获取、绩效、合规、人的行为六项原则。A 是 PDCA；C 是风险管理过程；D 是项目过程组。

**6. B**　解析：确定风险容忍度、审批重大风险事项，是治理层的典型动作。A 窄化了风险管理的层级；C 把最终责任错放到项目经理；D 忽视了风险管理正是治理三大任务之一。

**7. B**　解析：需要覆盖全流程的控制目标体系并支撑审计与治理评价，正是 COBIT 的适用场景。A 管服务流程；C 管软件开发过程能力；D 是质量管理体系标准，都不以 IT 控制目标为核心。

**8. B**　解析：管理储备＝800×10%＝80 万元；项目总预算＝成本基准＋管理储备＝880 万元；动用 50 万元后剩余 80－50＝30 万元。注意成本基准始终是 800 万元不变，动用管理储备不会修改成本基准，这也是案例题最常挖的坑。

**案例小问（判断改错）参考答案要点**：

- （1）**错误**。说反了。**COBIT** 是 IT 治理与控制框架，**ITIL** 是 IT 服务管理最佳实践。
- （2）**正确**。资源管理任务的核心就是统筹配置、避免重复建设与资源闲置，追求同等投入下的更高产出。
- （3）**错误**。管理储备**不包含**在成本基准内，用于应对未知风险，动用须经**高层（治理层）批准**；包含在成本基准内、项目经理可动用的是**应急储备**。
- （4）**正确**。IT 治理承接公司战略、向公司治理反馈 IT 价值与风险，二者是延伸与支撑的关系，层级不能颠倒。
