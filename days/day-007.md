## ② 核心知识精讲

### 2.1 大数据：5V 说清"大"在哪，五步说清"怎么用"

大数据不是"数据多"，而是数据在规模、类型、速度上超出了传统工具的处理能力。教材用 **5V** 概括其特征：

| 特征 | 含义 | 常考提示 |
|---|---|---|
| Volume 大量 | 数据规模从 TB 到 PB、EB 级 | 起始规模、海量存储 |
| Variety 多样 | 结构化、半结构化、非结构化并存 | 非结构化占比高 |
| Velocity 高速 | 产生快、要求处理快 | 实时/流式处理 |
| Value 价值密度低 | 单位数据价值低，总量价值大 | 最容易被曲解的一条 |
| Veracity 真实性 | 数据质量与可信程度 | 噪声、缺失、造假 |

"价值密度低"是最爱挖坑的一条：它的意思是**从海量数据里提炼价值的难度大**，不是"大数据没价值"。视频监控一天的数据里，有用的可能只有几秒——密度低，但价值可能极高。

处理流程可以按"采、存、算、用"四段记，教材语境下把治理贯穿始终：

1. **数据采集与预处理**：从业务系统、日志、传感器、埋点采集，做清洗、去重、转换、补全；
2. **数据存储**：分布式文件系统、NoSQL、数据仓库、数据湖按需承载；
3. **数据计算与分析**：批处理、流处理、图计算、查询分析，做统计、挖掘、机器学习；
4. **数据展示与应用**：报表、可视化、标签画像、智能推荐、辅助决策；
5. **数据治理贯穿全过程**：标准、质量、安全、元数据、生命周期管理。

> **记忆抓手**：采存算用一条线，治理贯穿在中间；5V 里 Volume、Variety、Velocity 是"体量大、花样多、跑得快"，Value 和 Veracity 是"值钱但不可全信"。

### 2.2 从 Hadoop 到 Spark，再到数据湖

Hadoop 是批处理时代的标准答案，三个核心组件各管一段：

- **HDFS**：分布式文件系统，把大文件切块多副本存放，解决"存得下、不丢失"；
- **MapReduce**：分布式批处理计算模型，分而治之，解决"算得动"，但磁盘读写多、延迟高；
- **YARN**：集群资源管理与调度，解决"谁来分配 CPU 和内存"。

生态圈里还有几位常客：**Hive**（把 SQL 翻译成 MapReduce/Spark 任务的数据仓库工具）、**HBase**（面向列的 NoSQL 数据库，适合海量稀疏数据的随机读写）、**Sqoop**（关系数据库与 HDFS 之间搬数据）、**Flume**（日志采集）、**ZooKeeper**（分布式协调）。

**Spark** 是 Hadoop 之后的主力计算引擎。它的优势一句话说清：**基于内存计算、用 DAG 调度减少中间落盘**，因此在迭代计算和交互式查询上比 MapReduce 快得多。组件包括 Spark Core、Spark SQL、Spark Streaming、MLlib（机器学习）、GraphX（图计算）。

**数据湖**是近几年必考的新概念：它以原始格式集中存储任意类型、任意规模的数据，采用"**读时模式**"（先存后定义结构），适合把原始数据先沉淀下来再探索；**数据仓库**则要求"**写时模式**"（入库前先建模），数据结构化、面向主题、相对稳定、反映历史变化，适合稳定的报表与决策分析。

| 对比项 | 数据仓库 | 数据湖 |
|---|---|---|
| 入库方式 | 先建模、写时模式 | 原样存储、读时模式 |
| 数据类型 | 以结构化为主 | 结构化、半结构化、非结构化 |
| 典型使用者 | 报表与 BI 分析人员 | 数据科学家、算法与探索分析 |

实际项目中两者常常并存，业界把它叫"湖仓一体"——湖里存原始数据，仓里存加工后的主题数据。

### 2.3 区块链：一本谁都改不了的账

区块链本质上是一个**分布式账本**：数据以区块为单位、按时间顺序首尾相连成链，由多方共同维护，任何一方都无法单方面篡改。它的技术组成有四块：

1. **分布式账本**：每个节点保存一份完整或部分账本，不依赖单一中心记账；
2. **密码学技术**：哈希保证区块内容不可篡改，非对称加密与数字签名保证身份与不可抵赖；
3. **共识机制**：让互不信任的节点对"下一块记什么"达成一致，常见有 PoW（工作量证明，算力竞争、耗能高）、PoS（权益证明）、DPoS（委托权益证明）、PBFT（实用拜占庭容错，适合节点数量可控的联盟链）；
4. **智能合约**：部署在链上的程序代码，条件满足即自动执行，把"信任人"变成"信任代码"。

特征记五个词：**去中心化、不可篡改、可追溯、集体维护、公开透明**（联盟链、私有链的透明范围受准入控制限制）。

按准入方式分三类，这是选择题最高频的判断：

| 类型 | 准入与参与 | 典型定位 |
|---|---|---|
| 公有链 | 任何人可自由加入、参与共识 | 完全开放，如公开的数字货币网络 |
| 联盟链 | 需准入，若干机构共同治理 | 多方协作、半开放，如跨机构存证 |
| 私有链 | 单一组织内部使用 | 内部审计、内部流程留痕 |

判断口诀：**看"谁能进、谁记账"**。题干里出现"多家单位共同维护""需经审核才能加入节点"，一律选联盟链；出现"企业内部""仅本公司节点"，选私有链。

> **记忆抓手**：区块链 = 一本账 + 一把锁 + 一套投票规则 + 一段自动执行的代码。账本是分布式账本，锁是密码学，投票是共识机制，代码是智能合约。

### 2.4 在项目里怎么用：先问"有没有多方不互信"

大数据项目的落点通常是：用户画像与精准营销、风险与欺诈识别、设备预测性维护、经营分析驾驶舱。要写进案例或论文时，重点讲清"数据从哪来、怎么治理、支撑了什么决策"，而不是罗列技术名词。

区块链的适用前提只有一条：**存在多个互不信任的参与方，且需要共享一份可信记录**。所以存证溯源、供应链金融、跨部门数据共享、版权登记是它的主场；而单一组织内部的普通业务系统，用数据库加权限控制更省成本——这也是命题人常设的反向选项。

| 技术 | 解决的问题 | 不适用的情况 |
|---|---|---|
| 大数据 | 海量多源数据的存储与分析 | 数据量小、实时性要求极高且无需历史分析 |
| 区块链 | 多方互信与数据不可篡改 | 单方内部系统、高频低价值的小额交易 |

## ③ 高频易错点

1. **易错点**：把"价值密度低"理解成"大数据没价值"。 → **正解**：价值密度低指单位数据的价值低、需要挖掘，总量价值反而更大；这是大数据需要分析技术的根本原因。
2. **易错点**：把 MapReduce 当成实时流处理框架。 → **正解**：MapReduce 是磁盘型批处理，延迟高；实时流处理靠 Spark Streaming、Flink 这类引擎。考题给"毫秒级""实时"，就别选 MapReduce。
3. **易错点**：认为 HDFS 可以用来做随机读写和实时查询。 → **正解**：HDFS 适合一次写入、多次读取的大文件顺序访问；随机读写交给 HBase 这类 NoSQL。
4. **易错点**：把数据湖当"更便宜的数据仓库"。 → **正解**：核心差异是模式（schema）施加的时机——数仓写时模式、先建模；数据湖读时模式、先原样存。湖适合探索，仓适合稳定报表。
5. **易错点**：所有场景都想上区块链。 → **正解**：区块链的代价是性能与存储开销。没有"多方不互信"这个前提，用中心化数据库加审计日志更合理。

## ⑤ 参考答案与解析

**答案速查：1.B　2.A　3.C　4.B　5.C　6.B　7.B　8.C**

**1. B**　解析：价值密度低说的是"单位数据的价值含量低"，需要靠分析挖掘把价值提炼出来，总量价值反而大。A 把"密度低"错解为"总量小"；C 混淆了价值密度与数据质量（后者对应 Veracity）；D 描述的是时效性，不是 5V 中的 Value。

**2. A**　解析：清洗、去重、转换、补全都属于预处理，是采集环节的收尾动作，为后续存储和计算准备可用数据。B 存储解决"放得下"；C 计算分析解决"算得出"；D 展示应用解决"看得懂、用得上"。

**3. C**　解析：YARN 是资源管理与调度层，负责给各类计算任务分配 CPU、内存等集群资源。A 是分布式文件系统，管存储；B 是批处理计算模型；D 是基于 Hadoop 的数据仓库工具，把 SQL 转成分布式任务。

**4. B**　解析：Spark 的核心优势是把中间结果尽量留在内存，并用 DAG 划分阶段、减少不必要的落盘，所以迭代类算法和交互查询提升明显。A 与事实相反，Spark 能处理多种数据类型；C 错，Spark 常跑在 HDFS 之上；D 是数据仓库的特征，与计算引擎速度无关。

**5. C**　解析：原始多格式数据先原样沉淀、后续再定义结构，正是数据湖"读时模式"的典型用法。A 关系库难以承载海量非结构化数据；B 数据仓库要求入库前建模；D 数据集市是面向部门主题的小型数仓，更不适合存原始数据。

**6. B**　解析：PBFT 通过多轮投票达成一致，在节点数量可控、有准入的联盟链里确认快、能耗低，是主流选择。A 把 PoW 与 PoS 说反了，PoW 拼算力、耗能高；C 混淆了共识机制与加密技术，共识解决"记什么"，加密解决"谁能看、能否抵赖"；D 错，私有链同样需要共识，只是参与节点少、可采用简单算法。

**7. B**　解析：多家机构共同治理、节点须审核准入、只对联盟成员开放，三个特征齐了就是联盟链。A 公有链无需准入；C 私有链是单一组织内部；D 侧链是与主链双向锚定的辅助链，与准入方式不是同一分类维度。

**8. C**　解析：2 亿×500 字节＝1000 亿字节＝100 GB/天；3 副本后 300 GB/天；×365≈109500 GB，约 110 TB。选 A 是忘了算 3 副本（100 GB×365≈36.5 TB）；选 D 是把副本数当成了 9 倍量级。

**案例小问（判断改错）参考答案要点**：

- （1）**错误**。数据湖采用**读时模式**，数据原样入湖、使用时再定义结构；先建模再入库的是**数据仓库（写时模式）**。
- （2）**错误**。MapReduce 是**磁盘型批处理**模型，延迟高；毫秒级实时流处理应使用 **Spark Streaming、Flink** 等流计算引擎。
- （3）**错误**。联盟链是**许可链**，节点须经审核授权才能加入，账本数据的可见范围也由联盟规则控制；完全自由加入的是**公有链**。
- （4）**正确**。智能合约的本质就是把业务规则代码化，条件触发即自动执行，这正是它"用代码建立信任"的价值所在。
