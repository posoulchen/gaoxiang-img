## ② 核心知识精讲
### 2.1 项目集：一组必须绑在一起做的项目
**项目集**是一组**相互关联且被协调管理**的项目、子项目集和项目集活动，以便获得**分别管理所无法获得的效益**。

定义不长，但三个关键词一个都不能少，考场上就抓这三个：

- **相互关联**：组件之间有真实的依赖——共享基础设施、共享数据标准、共享供应商、前后衔接的交付物。没关联的项目堆在一起，不叫项目集；
- **被协调管理**：不是各管各的，而是统一规划进度、统一调配资源、统一管理接口与风险；
- **增量效益**：绑在一起做，能拿到单独做拿不到的收益。这是项目集存在的**唯一理由**。

举个例子：某市"一网通办"工程下面有政务云平台、数据共享交换平台、统一身份认证、事项管理系统四个项目。单看每一个都能验收，但只有协调起来，才能实现"一次登录、全网通办"。这个体验就是增量效益。

注意区分两个常混的说法：**项目集**为效益而协调关联项目；**项目组合**（明天讲）为战略而管理一批不一定相关的项目。前者靠"关联"，后者靠"战略与资源"。

### 2.2 项目集与项目的四个差别
这不是文字游戏，是案例分析的判断依据：

| 维度 | 项目 | 项目集 |
|---|---|---|
| 目标 | 交付特定的产品、服务或成果 | 实现战略效益，获取增量收益 |
| 成功标准 | 范围、进度、成本、质量达标并通过验收 | 效益实现、干系人满意、组织能力提升 |
| 管理重点 | 交付可交付成果，控制基准 | 组件间依赖协调、资源统筹、效益管理 |
| 变更与终止 | 尽量控制变更，目标达成即结束 | 接受为优化效益所必需的变更，效益不再需要或无法实现才结束 |

一句话概括：**项目经理对"交付"负责，项目集经理对"效益"负责**。这句在案例里非常好用——凡是"每个项目都按时验收了，但整体目标没实现"的情景，错的往往是项目集层面没人管效益、没人管依赖。

再补一条容易被忽略的差别：项目集的生命周期比项目长，且组件项目可以**分批启动、提前关闭**。某个组件项目做完了，不代表项目集结束；某个组件被终止，也不代表项目集失败——只要整体效益还能实现。

### 2.3 五大绩效域：项目集的五根柱子
项目集管理围绕五个绩效域展开，名字要背准：

| 绩效域 | 管什么 |
|---|---|
| 战略一致性 | 项目集必须支撑组织战略目标，靠商业论证把关 |
| 效益管理 | 效益的识别、分析规划、交付与维持 |
| 干系人参与 | 面向高管、监管方、合作伙伴等更高层级干系人 |
| 治理 | 决策、授权、监督与裁决，由治理机构承担 |
| 生命周期管理 | 定义、交付、收尾三个阶段的有序推进 |

记法：**战、效、人、治、命**——战略、效益、干系人、治理、生命周期。五个词按"为什么做、图什么、跟谁打交道、谁拍板、怎么走完"的顺序排，比死背顺序好记。

绩效域不是五份文档，而是五条"必须持续盯住"的线。考试常问"下列哪项不属于项目集管理绩效域"，干扰项一般是范围管理、质量管理、沟通管理这些**知识领域**名称——绩效域和知识领域是两套语言，别串台。

### 2.4 效益管理与项目集治理
**效益**是组织期望的、由项目集成果带来的可度量改善。它有三个特征要抓住：**可度量**（有指标、有基线）、**有时滞**（成果交付之后才逐步显现）、**需承接**（要靠运营接住才留得下）。

效益管理四步：**效益识别 → 效益分析与规划 → 效益交付 → 效益维持**。

最容易失分的是最后一步。案例里的经典场景：系统上线了、验收了、项目组撤了，一年后一查，使用率不到两成，效益根本没发生。这时候正确答法不是"项目失败"，而是：**缺少效益移交与效益维持机制**——没有明确运营承接方、没有设定效益指标与跟踪周期、没有把效益责任移交给业务部门。效益不是交付的自动结果，它需要有人接着管。

**项目集治理**由三个角色撑起来：**项目集发起人**（提供资源与高层支持、对战略对齐负责）、**项目集治理委员会/指导委员会**（批准章程与商业论证、批准组件项目启动与终止、裁决资源冲突、决策重大变更）、**项目集管理办公室**（提供流程、工具、报告与监控支持）。

治理与管理的分工，一句话：**治理管"该不该做、值不值、要不要停"，管理管"怎么做成"**。

**项目集经理**的角色，答题时按五条写：对项目集整体**效益实现**负责；协调组件项目间的**依赖关系**（资源、接口、里程碑）；统筹项目集层面的**风险与变更**；指导和支持各项目经理；与发起人、高管及外部伙伴保持沟通。能力上，战略思维、商业敏锐度、干系人管理与领导力的权重要明显高于技术专精。

> **记忆抓手**：项目集 = 关联项目 + 协调管理 + 增量效益；五大绩效域"战效人治命"；四步效益"识别—规划—交付—维持"，最怕停在交付；项目经理管交付，项目集经理管效益。

## ③ 高频易错点
1. **易错点**：把项目集理解成"规模大一点的项目" → **正解**：项目集的核心是**相互关联的组件 + 协调管理 + 增量效益**，规模大小不是判断标准；无关的大项目堆在一起也不构成项目集。
2. **易错点**：认为项目集的成功标准是"所有组件项目都通过验收" → **正解**：项目集的成功标准是**效益实现**与战略目标达成；组件都验收了但效益未实现，项目集仍不算成功。
3. **易错点**：把"范围管理""质量管理"当成项目集绩效域 → **正解**：项目集五大绩效域是**战略一致性、效益管理、干系人参与、治理、生命周期管理**；范围、质量等是项目层面的知识领域。
4. **易错点**：认为效益会随交付自动实现 → **正解**：效益需要**效益移交与效益维持**，要有运营承接方、度量指标与跟踪机制，否则"上线即终点"。
5. **易错点**：认为项目集经理应当直接指挥各组件项目的日常执行 → **正解**：组件项目的日常交付由**项目经理**负责；项目集经理负责协调依赖、统筹资源、管理项目集层面风险与效益。

（1）项目集就是规模较大、周期较长的单个项目。

## ⑤ 参考答案与解析
**答案速查**：1.B　2.D　3.C　4.A　5.C　6.B　7.A　8.C

**1. B**　解析：项目集是相互关联且被协调管理的项目、子项目集与项目集活动，目的是获得分别管理无法获得的效益。A 混淆了项目集与大型项目；C 描述的是项目组合；D 只是组织归属，不构成项目集的定义要件。

**2. D**　解析：项目集以效益实现和战略目标达成为成功标准；项目以交付成果通过验收为标准。A 把项目集降格为"组件按期完工"；B 项目集不只考核成本；C 把两者标准说反了。

**3. C**　解析：质量管理是项目层面的知识领域，不属于项目集五大绩效域。A、B、D 与"战略一致性、效益管理、生命周期管理"一一对应，都是绩效域。

**4. A**　解析：效益管理依次为效益识别、效益分析与规划、效益交付、效益维持。B 把交付提到识别之前；C、D 打乱了识别、规划、交付、维持的逻辑次序。

**5. C**　解析：批准项目集章程与商业论证、批准组件项目启动与终止，属项目集治理机构的决策职责。A 项目经理无此权限；B 配置管理员管配置项与版本；D 项目管理办公室提供支持，不承担治理决策。

**6. B**　解析：组件间依赖与资源冲突属项目集经理的统筹协调范围，重大冲突提交项目集治理机构裁决。A 把项目集问题下放给单个项目；C 让客户代替治理；D 未经评估直接暂停，可能损害整体效益。

**7. A**　解析：组件全部验收但效益未显现，典型原因是缺少效益移交与效益维持——没有运营承接方、没有效益指标与跟踪机制。B 若有大量缺陷，验收与运行会直接暴露；C 范围问题会表现为功能缺失，与"效率没提升"不对应；D 阶段划分错误不是效益不达的常见直接原因。

**8. C**　解析：项目集生命周期分为定义、交付、收尾三个阶段。A 是项目的过程组；B 是常见产品/系统生命周期的划分方式；D 是项目组合管理的活动顺序，都不对应项目集生命周期。

**判断改错题参考答案**

（1）**错误**。项目集是**一组相互关联且被协调管理的项目、子项目集和项目集活动**，目的是获得**分别管理所无法获得的效益**；规模与周期不是判断标准。

（2）**错误**。项目集的成功标准是**效益实现与战略目标达成**；组件项目全部验收但整体效益未实现，项目集仍不能判定为成功。

（3）**正确**。项目集管理五大绩效域为**战略一致性、效益管理、干系人参与、治理、生命周期管理**。

（4）**错误**。效益需要**效益移交与效益维持**，明确运营承接方、设定效益度量指标并持续跟踪，不会随交付自动实现。

（5）**正确**。组件项目日常执行由**项目经理**负责；**项目集经理**负责协调组件间依赖、统筹资源、管理项目集层面风险与变更，并对**整体效益**负责。
