## ② 核心知识精讲

### 2.1 计算机组成与存储体系

现代计算机遵循冯·诺依曼结构，由**运算器、控制器、存储器、输入设备、输出设备**五大部件构成。CPU 由运算器和控制器组成：运算器做算术与逻辑运算，控制器负责取指令、译码、发控制信号。部件之间靠总线连接，总线分**数据总线、地址总线、控制总线**。

存储体系是一座金字塔，从上到下：**寄存器 → 高速缓存（Cache）→ 主存 → 辅存（硬盘、固态盘）→ 脱机存储（磁带、光盘）**。规律只有一条：**越往上速度越快、容量越小、单位成本越高**。Cache 不是为了"内存不够用"，而是按局部性原理在速度与成本之间做折中，让 CPU 不必每次等主存。

容量换算要熟：1 Byte = 8 bit，1 KB = 1024 B。带宽折算容量是唯一可能动笔的地方：

> **容量（MB）＝ 码率（Mbps）× 时间（秒）÷ 8**

微型算例：8 Mbps 的摄像头录 1 小时，8 × 3600 ÷ 8 = 3600 MB ≈ 3.6 GB。忘了除以 8 就成 28.8 GB——那是把比特当成了字节，最常见的错。

### 2.2 操作系统与软件分类

软件分系统软件与应用软件。操作系统是最基本的系统软件，五大功能是**进程管理（处理机管理）、存储管理、文件管理、设备管理、作业管理**。

按特性分：批处理（成批提交、吞吐量大）、分时（多用户轮流、交互性好）、实时（严格时限内响应，如工控、车载）、网络、分布式、嵌入式。考法通常是"某场景选哪种"：硬实时控制选实时操作系统，多用户共享主机选分时，批量数据处理选批处理。

### 2.3 网络分层：OSI 七层与 TCP/IP 四层

OSI 从下到上七层：**物理层、数据链路层、网络层、传输层、会话层、表示层、应用层**。TCP/IP 四层：网络接口层、网际层、传输层、应用层。

| OSI 层 | TCP/IP 对应 | 关键协议与设备 |
|---|---|---|
| 应用层/表示层/会话层 | 应用层 | HTTP、FTP、SMTP、DNS |
| 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网际层 | IP、ICMP、路由器 |
| 数据链路层/物理层 | 网络接口层 | 以太网、交换机、集线器 |

各层职责抓一句：物理层传比特，数据链路层管相邻节点的帧与差错，网络层负责寻址与路由，传输层负责端到端传输，会话层管会话建立与同步，表示层管格式转换与加密压缩，应用层直接面向业务。

TCP 与 UDP 必考：TCP **面向连接、可靠、有序**，有确认重传、流量控制与拥塞控制，代价是开销大、时延抖动；UDP **无连接、开销小、不保证可靠**，适合实时音视频、直播、DNS 查询这类"宁丢不等"的场景。一句记牢：**要可靠用 TCP，要快用 UDP**。

### 2.4 常用端口：背下来直接得分

| 端口 | 协议 | 用途 |
|---|---|---|
| 20/21 | FTP | 文件传输（21 控制、20 数据） |
| 22 | SSH | 加密远程登录 |
| 23 | Telnet | 明文远程登录 |
| 25 | SMTP | 发送邮件 |
| 53 | DNS | 域名解析 |
| 80/443 | HTTP/HTTPS | 网页浏览，443 加密 |
| 110 | POP3 | 接收邮件 |
| 161 | SNMP | 网络管理 |
| 3389 | RDP | 远程桌面 |

> **记忆抓手**：20/21 传文件、22 加密登、23 明文登、25 发信、110 收信、53 找域名、80/443 看网页、161 管网络、3389 远程桌面。**"发信用 25，收信用 110"，这一对最容易反。**

### 2.5 网络设备、拓扑与 5G

设备按所在层记：**集线器、中继器**在物理层（共享带宽、冲突多）；**交换机**在数据链路层（按 MAC 转发、划分冲突域）；**路由器**在网络层（按 IP 路由、隔离广播域）；**网关**做高层协议转换；**防火墙**做访问控制。判断题最爱问"交换机工作在哪一层"——普通交换机在数据链路层，三层交换机才具备路由能力。

拓扑五种：总线（成本低、故障难定位）、星型（易扩展、依赖中心节点）、环型（令牌传递、时延确定）、树型（分层管理、适合园区）、网状（可靠性最高、成本最高，骨干网常用）。

5G 三大应用场景：**eMBB** 增强移动宽带（超高清视频）、**URLLC** 低时延高可靠（工业控制、远程驾驶）、**mMTC** 海量机器类通信（海量传感器）。指标记三个数：用户体验速率 100 Mbps、空口时延 1 ms、连接密度每平方公里 100 万台。

### 2.6 存储三兄弟与数据库分类

| 类型 | 连接方式 | 特点与场景 |
|---|---|---|
| DAS 直连式存储 | SCSI/FC 直连磁盘阵列 | 块级、成本低、扩展性差，适合单机小规模 |
| NAS 网络附加存储 | 以太网 + NFS/CIFS | 文件级、部署简单，适合文件与办公共享 |
| SAN 存储区域网络 | FC 或 iSCSI 专用存储网络 | 块级、高带宽低时延，适合核心数据库 |

数据库按模型分：关系型用二维表和 SQL（Oracle、MySQL、SQL Server），适合结构化数据与强一致事务；非关系型（NoSQL）包括键值型（Redis）、文档型（MongoDB）、列族型（HBase）、图数据库（Neo4j），适合海量、半结构化、高并发或复杂关系场景。

按处理场景还分 OLTP 与 OLAP：OLTP 面向日常事务，高并发、小事务、实时响应；OLAP 面向分析决策，大批量聚合、数据量大。数据仓库通常承担 OLAP 角色，这是后面数据管理章节的伏笔。

> **记忆抓手**：存储记"直连、文件、块"——DAS 直连、NAS 给文件、SAN 给块；分层记"物数网传会表应"，从下往上数。

## ③ 高频易错点

1. **易错点**：认为交换机工作在网络层 → **正解**：普通交换机在数据链路层按 MAC 转发；路由器才在网络层按 IP 转发，三层交换机是兼具路由功能的例外。
2. **易错点**：把 21、22、25、110 记混 → **正解**：21 是 FTP 控制端口、22 是 SSH、25 是 SMTP 发信、110 是 POP3 收信。"发 25 收 110"要形成条件反射。
3. **易错点**：以为 TCP 适合所有实时场景 → **正解**：重传与拥塞控制会带来时延抖动，实时音视频、直播多用 UDP。可靠与实时在这一题里是对立的。
4. **易错点**：把 NAS 当成性能最高的存储方案 → **正解**：NAS 是文件级、走以太网，方便共享但性能一般；要高带宽低时延的块级访问，选 SAN。
5. **易错点**：算容量时漏掉除以 8 → **正解**：Mbps 是比特每秒，存储用字节。8 Mbps 录 1 小时约 3.6 GB，不是 28.8 GB。

**二、判断改错（3 小题，每题 2 分）**

今日无案例题，专注选择题。下面 3 句先判对错，错的写出错在哪里并改正：

2. 5G 的三大应用场景是 eMBB、URLLC 和 mMTC。

## ⑤ 参考答案与解析

**一、单选题**

1.B　2.A　3.C　4.D　5.C　6.C　7.A　8.B

**1. B**　解析：控制器负责取指令、译码、发控制信号并协调各部件。A 运算器只做算术与逻辑运算，C 负责数据存放，D 负责数据录入。

**2. A**　解析：存储体系由快到慢为寄存器、Cache、主存、硬盘。B、C、D 都把相邻两级或整体顺序颠倒，是典型的顺序干扰项。

**3. C**　解析：容量 = 码率 × 时间 ÷ 8 = 8 × 3600 ÷ 8 = 3600 MB ≈ 3.6 GB。D 是忘记除以 8 的结果，A、B 数量级不对。

**4. D**　解析：传输层负责端到端传输，TCP 在此层提供重传、流量控制与拥塞控制。A 负责寻址路由；B 管会话建立与同步；C 只管相邻节点的帧传输与差错检测。

**5. C**　解析：SSH 用 22 端口。A 错，SMTP 是 25，110 是 POP3；B 错，POP3 是 110，25 是 SMTP；D 错，DNS 是 53，80 是 HTTP。

**6. C**　解析：SAN 通过 FC 或 iSCSI 构建专用存储网络，提供块级、高带宽、低时延访问且可与业务网络隔离。A 扩展性差；B 是文件级共享，性能一般；D 用于离线归档。

**7. A**　解析：TCP 面向连接、可靠、有序。B 描述的是 UDP 特性；C 描述的是 TCP 机制；D 错，直播多用 UDP/RTP，用 TCP 反因重传造成卡顿。

**8. B**　解析：终端接入与网段划分用交换机（按 MAC 转发、划分冲突域），跨网段访问控制用路由器（按 IP 路由、隔离广播域）。集线器与中继器在物理层，做不到网段划分与访问控制。

**二、判断改错**

1. **错误**。NAS 通过以太网提供文件级共享（NFS/CIFS），部署简单但性能一般；通过光纤通道提供块级访问、性能更高的是 SAN，两者说反了。
2. **正确**。5G 三大应用场景即 eMBB 增强移动宽带、URLLC 低时延高可靠、mMTC 海量机器类通信。
3. **错误**。普通交换机工作在数据链路层，按 MAC 地址转发数据帧；按 IP 地址转发、工作在网络层的是路由器（三层交换机兼具路由功能，但不能以偏概全）。
