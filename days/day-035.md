## ② 核心知识精讲
### 2.1 制订进度计划：把估算装进时间轴
**制订进度计划是分析活动顺序、持续时间、资源需求和进度制约因素，创建项目进度模型的过程。** 它的核心输出是**进度基准**——经过批准的进度模型，是后续控制进度的比较基准，此外还包括项目进度计划、进度数据、项目日历等。

主要工具与技术：**进度网络分析、关键路径法、资源优化、数据分析（假设情景分析、模拟）、提前量与滞后量、进度压缩、项目管理信息系统、敏捷发布规划**。排在最前面的就是关键路径法，它是整个进度管理的计算核心。

### 2.2 四个参数与两条规则
每个活动都有四个时间：
- **ES** 最早开始、**EF** 最早完成：`EF = ES + 工期`
- **LS** 最晚开始、**LF** 最晚完成：`LS = LF − 工期`

计算方法只有两条规则，背下来就能上手：
- **正推取大**：`ES = 所有紧前活动 EF 的最大值`（前面全干完，我才能开始）
- **逆推取小**：`LF = 所有紧后活动 LS 的最小值`（不能拖累任何一个后面的人）

两个时差，一字之差、意义完全不同：
- **总时差 TF = LS − ES = LF − EF**：在不影响**项目总工期**的前提下，活动可以拖延的时间
- **自由时差 FF = 紧后活动 ES 的最小值 − 本活动 EF**：在不影响**任何紧后活动最早开始**的前提下，可以拖延的时间

记住这个关系：**自由时差 ≤ 总时差**。总时差看的是"项目"，自由时差看的是"邻居"。总时差为 0 的活动就在关键路径上。

### 2.3 完整算例：一张 8 个活动的网
某项目活动及关系如下（工期单位：天）：

| 活动 | 工期 | 紧前活动 |
|---|---|---|
| A | 4 | — |
| B | 6 | A |
| C | 3 | A |
| D | 8 | B、C |
| E | 5 | D |
| F | 2 | A |
| G | 3 | F |
| H | 2 | E、G |

**正推（取大）**：A：ES=0、EF=4 → B：ES=4、EF=10 → C：ES=4、EF=7 → D：ES=max(10,7)=10、EF=18 → E：ES=18、EF=23 → F：ES=4、EF=6 → G：ES=6、EF=9 → H：ES=max(23,9)=23、EF=25。**总工期 25 天。**

**逆推（取小）**：H：LF=25、LS=23 → E：LF=23、LS=18 → G：LF=23、LS=20 → D：LF=18、LS=10 → B：LF=10、LS=4 → C：LF=10、LS=7 → F：LF=20、LS=18 → A：LF=4、LS=0。

**时差汇总**：

| 活动 | 总时差 | 自由时差 |
|---|---|---|
| A、B、D、E、H | 0 | 0 |
| C | 3 | 3 |
| F | 14 | 0 |
| G | 14 | 14 |

于是关键路径为 **A→B→D→E→H**，长度 4+6+8+5+2=25 天，正好等于总工期。再看 C：它有 3 天总时差，因为 D 要等 B（第 10 天）才能开工，C 第 7 天就完了，空出的 3 天随便用，不影响项目。F 的总时差 14 天，但自由时差是 0——它一拖，G 就得等，只是 G 后面还有大量富余，所以不影响总工期。这个"F 总时差大、自由时差为 0"的例子，是理解两个时差区别的最好样本。

### 2.4 关键路径：最长的那条，决定最短的工期
**关键路径是网络图中总持续时间最长的路径**，它决定了项目的**最短可能工期**。路径上所有活动的总时差为 0，任何一个延误都会等额拖延项目完成日期。

三个必须记住的结论：
- **关键路径可能不止一条**。当两条路径长度相等且都是最长时，两条都是关键路径，此时压缩工期必须同时压两条，否则白压。
- **关键路径会变**。资源调整、范围变更、某个非关键活动拖延超过总时差，都可能让关键路径转移。
- **关键路径不是活动最多的路径**，也不是资源消耗最大的路径——只看**总持续时间最长**。

考场上最省时间的判断法：把所有从起点到终点的路径长度都列出来，最长的那条就是关键路径；先算总工期，再用它逆推，比逐个套公式快得多。

### 2.5 资源优化：平衡改路径，平滑不改
| 对比项 | 资源平衡 | 资源平滑 |
|---|---|---|
| 目的 | 解决资源供需冲突、资源超负荷 | 使资源需求波动最小 |
| 对工期与关键路径的影响 | 往往**改变关键路径、延长工期** | **不改变关键路径、不延长工期** |
| 局限 | 可能牺牲工期 | 可能无法实现所有资源优化目标 |

一句话：**资源平衡是"为了资源，可以动工期"；资源平滑是"不动工期，只把波峰削平"**。案例里"某关键资源被两个活动同时占用，项目经理推迟其中一个活动导致工期延后"——这是资源平衡，答"资源平滑"就错了。

### 2.6 进度压缩：赶工花钱，跟进担风险
| 对比项 | 赶工 | 快速跟进 |
|---|---|---|
| 做法 | 增加资源、加班、加人，缩短关键活动工期 | 把原本串行或部分串行的活动改为并行 |
| 代价 | **增加成本**，可能降低质量 | **增加返工与风险**，可能增加成本 |
| 适用 | 关键路径上的活动，且资源可获取 | 活动之间是选择性依赖，可安全并行 |

两条铁律：**压缩只压关键路径**（压非关键活动等于白花钱）；**不缩减范围**（缩范围需要客户批准，那是变更，不是压缩）。

> **记忆抓手**：正推取大、逆推取小；总时差看自己（对项目），自由时差看邻居（对紧后）；平衡动工期、平滑不动；赶工花钱、跟进担险。

## ③ 高频易错点
1. **易错点**：认为关键路径是"工期最短的路径"或"活动最多的路径" → **正解**：关键路径是**总持续时间最长**的路径，它决定项目最短可能工期。
2. **易错点**：把总时差与自由时差混用 → **正解**：总时差影响**项目总工期**，自由时差只影响**紧后活动的最早开始**；自由时差 ≤ 总时差，总时差为 0 的活动在关键路径上。
3. **易错点**：认为资源平滑会导致工期延长 → **正解**：**资源平滑不改变关键路径、不延长工期**；会延长工期、可能改变关键路径的是**资源平衡**。
4. **易错点**：压缩工期时去压非关键活动，或认为"加人就能减半工期" → **正解**：只有压**关键路径**上的活动才能缩短总工期；加人还受收益递减规律制约。
5. **易错点**：认为关键路径只有一条、且一旦确定不再变化 → **正解**：**可能有多条关键路径**，且随资源调整、变更、非关键活动拖延而转移。

**二、案例小问（1 题，10 分）**

【背景】某市"一网通办"平台二期项目，活动与依赖关系如下：A（4 天，无紧前）；B（6 天，紧前 A）；C（3 天，紧前 A）；D（8 天，紧前 B、C）；E（5 天，紧前 D）；F（2 天，紧前 A）；G（3 天，紧前 F）；H（2 天，紧前 E、G）。合同要求 23 天内上线。

【问题1】计算项目总工期并写出关键路径。（4 分）
【问题2】计算活动 C 与活动 G 的总时差和自由时差。（3 分）
【问题3】若要求提前 2 天完工，说明可采取的措施及需要注意的风险。（3 分）

## ⑤ 参考答案与解析
**答案速查**：1.B　2.D　3.A　4.D　5.C　6.A　7.D　8.C

**1. B**　解析：关键路径是总持续时间最长的路径，其长度等于项目最短可能工期。A 恰好说反；C 活动多不代表路径长；D 资源消耗与路径长度无必然关系。

**2. D**　解析：正推取大——某活动必须等所有紧前活动全部完成才能开始，故 ES 取紧前活动 EF 的最大值。A、C 取值对象错；B 是逆推法求 LF 的规则。

**3. A**　解析：总时差＝LS−ES＝LF−EF，两个式子等价。B 是工期；C、D 把起点终点交叉搭配，算出来的不是时差。

**4. D**　解析：TF=LS−ES=12−6=6 天，也可用 LF−EF=16−10=6 天验证。A、B、C 都是把时差与工期、浮动区间混淆后的错误值。

**5. C**　解析：自由时差是"不影响紧后活动最早开始"的机动时间。A 描述的是总时差；B 方向错，时差只约束后面；D 把自由时差与关键路径混为一谈。

**6. A**　解析：资源平衡为化解资源冲突而调整活动日期，往往改变关键路径、延长工期。B 是资源平滑的定义；C 是赶工；D 是快速跟进。

**7. D**　解析：赶工加资源换工期、增加成本；快速跟进并行作业、增加返工风险。A、B 把两种手段互换；C 缩减范围属范围变更，需客户批准，不是进度压缩手段。

**8. C**　解析：关键路径活动延误 3 天直接顺延总工期 3 天；总时差 5 天的活动延误 2 天未超时差，不影响总工期。A 简单相加；B 忽视了关键路径无时差；D 取了错误的时差消耗。

**案例参考答案要点**

**问题1（4 分）**
- 正推：A（0–4）→ B（4–10）、C（4–7）、F（4–6）→ D（10–18）→ E（18–23）→ G（6–9）→ H（23–25）。
- **总工期 25 天**（2 分）；**关键路径 A→B→D→E→H**（2 分）。
- 只写结果不列计算过程，酌情扣 1 分。

**问题2（3 分）**
- 活动 C：ES=4、EF=7、LS=7、LF=10，**总时差 3 天**；紧后 D 的 ES=10，**自由时差 10−7=3 天**（2 分）。
- 活动 G：ES=6、EF=9、LS=20、LF=23，**总时差 14 天**；紧后 H 的 ES=23，**自由时差 23−9=14 天**（1 分）。

**问题3（3 分）**
- 措施：①**赶工**——对关键路径上的活动（如 D、E）增加资源或安排加班；②**快速跟进**——把可安全并行的活动改为搭接，如 B 与 C 部分并行、D 与 E 搭接；③重新审视**选择性依赖**，优化网络逻辑；④调整**资源分配**，优先保障关键路径资源。
- 风险：赶工会**增加成本**并可能影响质量；快速跟进会增加**返工风险**；压缩后**关键路径可能转移**至原非关键路径（如 C 的 3 天时差被吃掉），需重新计算；**不得擅自缩减范围**，如确需缩减须经客户同意并走变更流程。
- 措施写全得 2 分，风险指出两点以上得 1 分。
